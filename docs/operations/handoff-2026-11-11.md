## Running the stack locally

- Start from a checkout of main: `docker compose -p pumpwatch --profile apps up -d --build` (Git Bash: prefix
  `MSYS_NO_PATHCONV=1`). Web at http://localhost. Use `localhost`, not `127.0.0.1`, in the browser.
- Every app container reads `.env` from the directory compose runs in (`env_file: .env`). A worktree without its own `.env`
  silently runs with every live source off. Copy the root `.env` into the worktree (it is gitignored) before starting.
- The owner's `.env` has `DATA_MODE=live`, Alpaca, SEC (with a real `SEC_USER_AGENT`), Bluesky and `SENTIMENT_ENABLED` on.
  Never print or commit its values.
- `GEMINI_API_KEY` is not set in any env file. Until the owner adds it, the assistant uses the mock agent. After it is
  added, restart research: `docker compose -p pumpwatch --profile apps up -d research`.
- Swing appears after 31 one-minute bars per ticker; the full model path after 391.
- The Postgres volume still holds about 50 scored tickers from an earlier load test run; they age out as live scores
  arrive.
- All containers were stopped (not removed) at the end of this session; volumes are intact.

## Gotchas found this session

- `mvn -o compile` does not compile tests; use `mvn -B test-compile` or the full CI before saying main is green.
- Kafka Streams tests on Windows collide on the shared state dir when two Maven runs overlap; give each run its own
  `-Djava.io.tmpdir` through `argLine`.
- Docker-backed tests (Testcontainers) are skipped when Docker Desktop is off; CI runs them.
- `gh issue close` with several issues in one command was refused by the permission check; one issue per command works.
- Score schema is version 2 and PostRecord schema is version 2; recordings made before those bumps fail strict validation.
